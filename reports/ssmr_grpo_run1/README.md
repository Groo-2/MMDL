# E1 결과: SSMR-Bench GRPO (`grpo_run1`)

작성 2026-11-02. 실습실 RTX 4090(24GB)에서 Qwen3-VL-4B-Instruct를 SSMR-Bench Train_visual로 GRPO 학습한 결과다.
MMMU 전체 900문항(`full2`)은 측정을 마쳤다(2026-11-04): **전체 점수는 62.83% -> 55.39%로 떨어졌다.**
이어서 MusiXQA로 학습할 팀원은 [HANDOFF_musixqa.md](HANDOFF_musixqa.md)를 먼저 읽을 것.

## 한눈에

| 평가 | base | grpo_run1 | 해석 |
|---|---|---|---|
| SSMR hold-out 400 (학습과 같은 분포, seed 42, 최대 8,192토큰) | 18.25% | **47.25%** (+29.0%p) | 큰 향상. 그중 98%는 base가 끝맺지 못해 잘렸던 문항에서 나옴 |
| MMMU Music 30문항, Avg@4 (seed 42~45) | 25.8% | 27.5% | +1.7%p, 95% 신뢰구간 [-14.2, +18.3]%p. **구분되지 않음** |
| MMMU Music 잘림 (run별, 30문항 중) | 14 / 15 / 14 / 17 | 2 / 0 / 1 / 0 | 잘림은 크게 줄었으나 정답은 늘지 않음 |
| **MMMU 전체 900, Avg@2** (seed 42, 43, 실습실 동일 조건) | **62.83%** (62.33 / 63.33) | **55.39%** (55.00 / 55.78) | **-7.4%p. 하락** |

## 재현에 필요한 설정

- 모델: `Qwen/Qwen3-VL-4B-Instruct` @ `ebb281ec70b05090aa6165b016eac8ec08e71b17`, bf16, 양자화 없음
- 환경: RTX 4090 24GB, WSL2, 드라이버 560.94(CUDA 12.6), Python 3.12(conda `mmdl`),
  torch 2.13.0+cu129, vLLM 0.27.1+cu129, transformers 5.19.0, TRL 1.16.0, PEFT 0.21.2
- 데이터: SSMR-Bench Train_visual(MIT) 중 **이미지 1장 문항만**(5,269개). base로 문항당 8번 풀어 통과율 1/8~7/8만 남기고
  카테고리 균형으로 1,120개 선택(Beat 365, Scale 315, Interval 280, Chord 160). Chord는 원본 1장 문항이 583개뿐이라 부족
- 학습: GRPO, 스텝당 8문항 × rollout 8, KL 없음(beta 0), `loss_type=grpo`, 정답 보상만(`music_ft/reward.py`, Llama judge 없음),
  LoRA r64/alpha128(LLM의 q,k,v,o,gate,up,down만, vision tower 제외), lr 2e-5 constant, micro-batch 1(grad accum 64),
  gradient checkpointing, max_completion 2048, temperature 0.7 / top_p 0.8 / top_k 20(평가와 같음),
  **rollout에는 presence_penalty 없음**(HF generate가 지원하지 않음), rollout은 HF generate, seed 42, 140스텝, 문항은 한 번씩만 사용
- 해상도: min_pixels 1,003,520 / max_pixels 4,014,080 (Qwen 공식 MMMU 평가 스크립트의 값과 같고 평가와 동일)
- 학습 시간: 35,690초(약 9.9시간), 중단·재시작 0회
- 평가: 동결 프롬프트(`mmmu_pro_cot`), 평가 sampling은 Qwen 공식 recipe(presence_penalty 1.5 포함), 최대 32,768토큰,
  규칙 파서 → Llama-3.1-8B-Instruct judge(`0e9e39f249a16976918f6564b8830bc894c89659`) → 오답

## MMMU 전체 900문항 (Avg@2, seed 42 / 43)

| | 실습실 base | grpo_run1 | 차이 |
|---|---|---|---|
| 전체 정확도 | 62.33% (561) / 63.33% (570) -> **62.83%** | 55.00% (495) / 55.78% (502) -> **55.39%** | **-7.4%p** |
| 잘림 (32,768토큰) | 89 / 98 | 66 / 55 | 줄었음 |
| 요청 오류 (오답 처리) | 0 / 7 | 0 / 7 | 재시도 전 |

- 실습실 base(62.83%)가 이전 Colab Run B(62.56%, A100)와 거의 같아서 **하드웨어·라이브러리 차이는 점수에 영향이 작다.** 하락은 학습 때문이다.
- 두 모델 모두 seed 간 차이가 1%p 미만이라 7.4%p 하락은 샘플링 노이즈가 아니다. 요청 오류 7건이 모두 정답이어도 0.8%p라 결론은 같다.
- 잘림은 줄었는데 점수가 떨어졌다. 끝낸 문항의 정확도가 약 69% -> 약 59%로 내려갔다(정답 수 / 끝낸 문항 수로 구한 대략값).
- Run B 대비 유형별(run_00): 객관식 847문항 64.0% -> 57.3%(-57문항), 주관식 53문항 39.6% -> 18.9%(-11문항). 가장 많이 떨어진 과목은 Finance(-26.7%p), Pharmacy, Physics, Management(각 -20.0%p)이고 계산 과목과 비계산 과목이 섞여 있다. 과목당 30문항이라 개별 과목은 노이즈가 크다.
- 같은 seed(42)로 과목별 비교: base 561 -> grpo 495, 21과목 하락/5과목 상승. **base 잘림이 0~1개인 14과목에서도 -30문항**이라 하락은 잘림과 무관하다. Math는 19 -> 18로 그대로다.
- Biology의 base 정답 -> grpo 오답 9문항 중 4개를 읽으면, grpo 응답은 모두 "Step 1, 2, 3 -> Answer"의 짧은 틀(111~238토큰)이고 base는 선택지를 비교하고 재검토하는 긴 풀이(363~1,958토큰)였다.
- **하락 원인은 아직 분리하지 못했다.** 유력한 가설은 학습 설정(최대 2,048토큰, 잘림 보상 0)이 "짧게 끝내기"를 보상해서 풀이 방식을 바꿨다는 것이고 시험하지 않았다. 다른 후보는 4지선다 편향, 정책 쏠림(entropy 0.03)이다.

## 해석과 한계

1. SSMR 향상의 대부분은 "끝까지 답을 내게 된 것"이다. base가 이미 끝내던 문항의 정확도는 사실상 그대로(+2/171). 풀이 실력이 올랐는지는
   이 데이터로 가를 수 없다. 모르는 문제에서 헤매다 반복에 빠진 것이 잘림의 원인일 가능성도 있어서 "실력이 늘지 않았다"고 단정하지 않는다.
2. MMMU Music에서도 잘림(약 50% → 2.5%)은 크게 줄었으나 정답은 늘지 않았다. 학습 모델은 거의 전부 답을 내는데 정확도가 27.5%이므로,
   base가 끝내지 못하던 문항에서는 정답이 거의 나오지 않은 것으로 읽힌다(두 평균에서 뽑은 추정이고 문항별 확인은 아님).
3. SSMR(규칙으로 만든 합성 문제) → MMMU Music(사람이 만든 실제 문제)의 분포 차이가 병목일 수 있다. 이번 결과로는 검증하지 못했다.
4. hold-out은 학습과 같은 분포라 오르는 것이 당연하다. 이 숫자만으로 MMMU 개선을 주장하지 말 것.
5. 학습 모델의 응답이 약 110토큰으로 짧아졌다. 전체 900문항은 아래 절처럼 오히려 떨어졌다.

## SSMR 논문과의 비교 (원문 Table 3, 4 직접 확인)

| | 논문(Qwen2.5-VL-7B-IT) | 우리(Qwen3-VL-4B) |
|---|---|---|
| SSMR 시각 문제 | 41.81% → 70.56% (+28.75%p) | 18.25% → 47.25% (+29.0%p) |
| MMMU Music (Avg@8) | 20.00% → 26.67% (+6.67%p, 3B는 +5.00%p) | 25.8% → 27.5% (+1.7%p, Avg@4) |

논문의 MMMU Music 향상은 원래 작아서(2문항) 우리 신뢰구간(±16%p) 안에 있다. "논문과 다르다"고 결론 낼 수 없다.
조건 차이: 논문은 스텝당 128문항 × 300스텝(우리의 약 34배: 38,400 대 1,120문항 분량), 8,000문항 전체, 논문 템플릿 사용. 우리는 8문항 × 140스텝, 1장 문항 1,120개, 동결 프롬프트, LoRA.
이 차이들이 결과에 얼마나 영향을 줬는지는 분리해서 시험하지 않았다.
