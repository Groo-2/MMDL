pilot20은 이 구성 선택에 사용했으므로 앞으로 독립적인 최종 테스트라고 부르지 않는다.

## 2. 학습 비중과 파일 역할

| 카테고리 | 기존 균등안 | 이번 학습 비중 | 학습용 문항 | 후보 풀 | 고정 holdout |
|---|---:|---:|---:|---:|---:|
| PitchReading | 25% | **60%** | 1,920 | 2,400 | 100 |
| KeySignature | 25% | **25%** | 800 | 1,000 | 100 |
| MeasureCount | 25% | **10%** | 320 | 800 | 100 |
| Clef | 25% | **5%** | 160 | 800 | 100 |
| 합계 | 100% | 100% | **3,200** | **5,000** | **400** |

- `train.jsonl`: 요청서의 후보 풀. 모든 카테고리가 800문항 이상이며 중복 제거/검수 탈락에 대비한 여분을 포함한다.
- `train_recipe.jsonl`: 위 후보 풀에서 선택한 3,200문항. ID·문제·선택지·정답이 후보 풀의 해당 행과 완전히 같다.
- `holdout.jsonl`: 원본 test 문서에서만 만든 400문항. 학습 비중에 맞춰 Clef를 5%로 줄이지 않는다.
- 모든 파일은 문서당 최대 2문항이며 train/test 문서 분리가 적용된다.
- 새 5,400문항에 기존 샘플 80개의 검수 완료 상태를 복사하지 않는다.

학습 로더의 기본 파일명은 `train.dedup.jsonl`이다. 이 기본값으로 후보 풀 전체를 학습하면
이번 60/25/10/5 비율이 적용되지 않는다. 중복 제거와 내용 검수를 마친 뒤
학습 시 `--train-file train_recipe.dedup.jsonl`을 명시해야 한다.

## 3. 카테고리 안의 정답 내용과 오답

### 조표

`7 flats … 1 flat / no sharps or flats / 1 sharp … 7 sharps`의 **15개 정답 내용을 균등 선별**한다.
800문항에서는 각 내용이 53~54개다. 샘플처럼 7 flats가 25%에 이르는 편중을 방지한다.
단 한 번의 플랫 오류를 근거로 플랫만 과도하게 늘리지는 않는다.
조표 0개는 샵/플랫을 뒤집어도 같으므로 인접한 비영 조표를 오답으로 사용한다.

오답 구성도 조정했다. 정답이 ±n일 때 반대 부호 -n을 포함하되, 보통 나머지 두 오답은 인접 개수 ±m의 쌍으로 만든다.
이렇게 하면 '두 번 나오는 숫자가 정답 개수'라는 단서를 줄일 수 있다. 이는 요청서 예시의 같은 부호 인접 개수 두 개를 확장한 규칙이다.
단, 0개가 정답으로만 등장하지 않도록 정답 개수가 1~2인 문항 중 일부에는 0개를 오답으로 넣는다.
숫자 위치 경고와 선택지 분포는 실제 출력에서 다시 측정하며, 이 조정이 모든 지름길을 제거했다고 주장하지 않는다.

### 음자리표

Clef 정답인 treble only / bass only / both를 균등 선별한다. 160문항에서는 53~54개씩이다.
원본 QA 전체에 alto only 정답이 없다는 한계는 남는다. 비중을 5%로 낮추어 쉬운 문제의 영향과
없는 정답 유형으로 생기는 지름길을 제한한다. 이를 완전한 네 정답 유형의 4지선다라고 해석하지 않는다.
거짓 alto 정답을 새로 만들거나 4지선다 형식을 임의로 바꾸지는 않는다.

### 음 높이

- 높은음자리표/낮은음자리표 각각 50% (학습용 960개씩).
- 1~3음 30%, 4~6음 45%, 7~8음 25% (576/864/480개). 원본의 긴 음열만 많이 들어가는 것을 줄이기 위한 설계 선택이다.
- 9음 이상은 기존 요청서대로 제외한다.
- 각 문항에 오선 위치 착각 오답을 하나 포함한다. ±1칸뿐 아니라 **±2칸**도 사용하여 pilot의 E4↔G4 같은 오류를 반영한다.
- 나머지 두 오답은 옥타브/임시표/음자리표 착각 중 두 유형을 골라 구성한다. 조합은 문항마다 달라진다.
- 정답 및 세 오답의 실제 음 높이 배열이 서로 다른지 검사한다. Bb를 Cb로 옮기는 오답과 Bb의 플랫을 제거한 B가 겹치는 식의
  한 음짜리 경계 사례는 전체 오답 조합을 다시 생성한다.
- 붙임줄 양쪽의 적힌 음표를 각각 센다는 기준을 질문에 명시한다.
- 원본 음열에서 샵/플랫이 보인다는 사실만으로 악보에 Natural 취소 기호가 인쇄됐는지는 알 수 없다.
  따라서 이번 설정이 Natural 취소 기호 학습을 충분히 포함한다고 주장하지 않는다.

### 마디 수와 A~D 위치

- 마디 수는 원본의 무작위 순위로 선별해 대체로 원본 분포를 유지한다. 실제 원본 9마디 문서는 train 160/86,400, test 14/9,600뿐이다.
  pilot20에는 마디 수 평가가 없으므로 이 드문 경계값을 1/11 비율로 과대표집하지 않는다. 반복 연주 횟수 제외 기준은 질문에 명시한다.
- 마지막 인쇄 번호를 마디 수로 간주하지 않는다. 알려진 번호 불일치 문서의 검증되지 않은 PitchReading은 계속 제외한다.
- 각 분할/카테고리에서 A~D가 정확히 25%이며, 조표·Clef의 개별 정답 내용 그룹 안에서도 최대한 균등하게 배정한다.
- 음 높이는 음자리표×음열 길이 그룹 안에서도 정답 위치가 한쪽으로 쏠리지 않게 한다.

## 4. 실행 및 중복 제거 이후 재선별

```powershell
.\.venv_lab\Scripts\python.exe -X utf8 music_ft/build_musixqa_recipe.py build
```

설정: [musixqa_pilot20_recipe.json](../music_ft/musixqa_pilot20_recipe.json).
기본 출력: `data/musixqa_mcq_pilot20_v1/`. 이미 있는 폴더는 덮어쓰지 않는다.
출력은 학습 전 준비용 초안이며 manifest의 내용 검수, 중복 제거, 이미지 토큰 측정은 pending으로 남는다.

MMMU 중복 검사와 내용 검수로 후보를 제외한 뒤, 남은 후보 풀에서 비율을 다시 맞춘다.
중복 검사 코드는 현재 MMMU Music의 dev/validation/test에 대해 검사하므로 실제 범위를 보고한다.

```powershell
.\.venv_lab\Scripts\python.exe -X utf8 music_ft/build_musixqa_recipe.py remix `
  --data-dir data/musixqa_mcq_pilot20_v1 `
  --input-file train.dedup.jsonl `
  --output-file train_recipe.dedup.jsonl
```

`remix`는 제공된 파일에서 부분집합을 선택할 뿐 중복 검사를 대신하지 않는다.
필요한 정답 내용/정답 글자 조합의 후보가 부족하면 명시적으로 실패한다. 중복 탈락 문항을 되살리거나
같은 문항을 복제해서 목표 수를 맞추지 않고 후보를 보충해야 한다.

기존 `select_ssmr.py --per-category`는 카테고리마다 같은 수를 선별하므로 그대로 쓰면 이번 비율이 사라진다.
GRPO용 1/8~7/8 통과율 선별을 추가할 경우, 선별 후 적격 후보에서 이 비율을 다시 적용해야 한다.
실제 적격 문항 수가 부족할 수 있으며, 모델을 돌리기 전에는 그 수를 알 수 없다.

## 5. 무엇으로 개선 여부를 판단할 것인가

- 처음 만든 400문항 holdout의 파일 해시를 고정하고, 이후 학습 비율을 바꿔도 같은 평가 파일을 사용한다.
- 카테고리별 정확도와 네 카테고리 macro 평균을 함께 보고한다. 쉬운 Clef의 학습 비중을 바꿔 평가 점수를 부풀리지 않는다.
- pilot20의 주관식 정확도와 새 4지선다 정확도는 직접 비교 가능한 동일 지표가 아니다.
- MMMU Music 및 전체 평가의 동결된 프롬프트·해상도·sampling·judge 조건으로 최종 전이를 확인한다.
- 신규 데이터는 카테고리별 50문항 이상 악보 대조와 마디 번호 확인이 필요하다. 주관식 pitch 재평가에서는 음 이름·임시표·옥타브를 모두 비교해야 한다.
- Duration/Rest/Ornament의 추가는 원본 라벨과 이미지 대응을 별도로 검증한 뒤 확장한다.

이번 단계에서 모델 학습이나 성능 향상 검증은 수행하지 않는다.
